# AxomRank development roadmap

Planning baseline: 11 October 2026. Phases are relative to kickoff and depend on capacity; they are not promised launch dates. Proposed roles below must be assigned by the owner.

## Build a credible Assam information platform from the learning app

Keep the learning journey useful while adding reviewed information in small, maintainable collections. This repository holds brand and editorial assets. Keep application code in the application repository and production records in the content repository; connect them through stable content IDs and versioned exports rather than copying the entire app into this asset library.

## Phase 1 — foundation, weeks 1–2

Owner leads; designer and bilingual editor contribute.

1. Select the canonical Rang Ghar logo source, confirm usage rights and produce vector, transparent, monochrome, reversed and small-size variants. Preserve the supplied artwork.
2. Approve this broader positioning; retain the existing education tagline and record proposed section names separately from live features.
3. Classify existing files using the catalog. Record rights, generation provenance, approval and publish status. Resolve unavailable imagery and missing cover files listed in the project import report.
4. Prepare five editable templates: practice question, explained answer, place guide, opportunity notice and correction. Add cover/end-card components for the square carousel series and vertical video.
5. Assign one content reviewer and one fluent Assamese reviewer. Define the correction process and where readers report errors.

Completion gate: an approved brand kit, working source files, five readable bilingual template samples, a named review owner and a usable asset catalog. The repository structure is prepared; the artwork and review decisions remain production work.

## Phase 2 — strengthen learning and publishing, weeks 3–6

Product owner, subject editor and content producer collaborate.

- Record the actual app flows for question practice, answer review and mock tests where available. Capture screenshots with sample/non-personal data; never invent product screens or scores.
- Release a manageable first 20-post cycle using the existing 10 discovery / 6 trust / 4 action allocation. Each post gets one objective and destination. Reuse existing plans rather than producing unrelated campaigns.
- Pilot repeatable series: Wrong Answer Clinic, Assam Explained and Our Place Our Question. Maintain a source pack, final caption, alt text and editable source for each published piece.
- Select 10 verified lessons to connect from social posts into the app. Check answers and language before scheduling. Use basic tracked links without collecting unnecessary personal data.
- Continue the Ahom book through research comparison and Chapters 6–9; do not promote Volume I as finished. Preserve disputed claims and research IDs.

Completion gate: 20 reviewed posts, 10 working lesson destinations, real app media and a first-month baseline for practice starts, completed sessions and corrections. Adapt cadence to actual capacity.

## Phase 3 — information pilot, weeks 7–12

Directory researcher, product developer and local contributors support the owner.

Choose one education directory and one places collection. Proposed pilot sizes: 25 college/programme records and 12 place guides across more than one region. These are planning targets, not current coverage. Use official institutional pages and local review; do not turn the existing college QA screenshot into verified directory data.

Every record needs a stable ID, category, district/place, English and Assamese title where reviewed, official source URL, exact source location, checked date, next review date, responsible editor, status and correction route. Programme records also need institution, awarding/affiliating body where verified, admission cycle and eligibility source. Separate enduring descriptions from dates, fees and deadlines that expire.

Build search and filters for the pilot records. Show sources and last checked dates. Add expiration handling for opportunity notices and a reviewed submission form. Public user contributions stay unpublished until checked.

Completion gate: the pilot records pass evidence and language review; search finds them; expired notices cannot appear as open; readers can submit corrections. Expand only after the update workload is measured.

## Phase 4 — broaden Assam coverage, months 4–6

Develop Culture, Opportunities and Everyday Assam collections around reader demand and reviewer capacity. Add selected district explainers, local-language audio, licensed field photography and contributor profiles. Include community-specific review for cultural content. Introduce a contributor agreement covering consent, credit, permitted reuse and corrections.

Publish service explainers that link to official portals. Never imitate official identity or describe AxomRank as a government authority. Time-sensitive notices need an expiry date and an owner checking the original notice. Defer a full news desk, statewide business directory, bookings and emergency dispatch features until each has a sustainable operational owner.

Completion gate: every new collection has a scope statement, editor, review cadence, coverage report and working correction process. No “all Assam covered” claim based on a small pilot.

## Phase 5 — durable knowledge infrastructure, months 6–12

Develop a structured Assam knowledge index connecting people, places, institutions, events and lessons. Add content version history, search evaluation, bilingual synonyms and accessible low-bandwidth presentation. Consider offline reading and audio where user feedback justifies them. Keep an editorial distinction between historical uncertainty and current factual updates.

An AI assistant is optional later work. It should answer from approved records, show supporting sources, respect expired information and say when it cannot establish an answer. Evaluate answer accuracy in English and Assamese before offering it as a brand promise.

## Decisions and dependencies

| Decision | Proposed default | Required evidence |
|---|---|---|
| Expansion sequence | Learn → education opportunities → places → culture/services | Reader requests and editor capacity |
| Languages | Complete English/Assamese core; other languages through qualified contributors | Fluent reviewers and accessibility checks |
| Monetisation | Explain existing learning offers; keep source access clear | Actual pricing and live inclusions |
| Source storage | Assets here, app code in app repo, structured production records in content repo | Stable IDs and documented export contract |
| Heavy binaries | Preserve imported originals now; plan LFS or object storage for future growth | Storage ownership, backup and successful restore test |

## Measure usefulness and reliability

Establish baselines before numeric growth goals. Track practice starts/completions, return visits, guide searches that find a useful record, official-link opens, notice expiry compliance, records reviewed on time and correction resolution time. Track cultural/region coverage without inferring that one contributor represents everyone.

Weekly: review the next content batch and expiring notices. Monthly: inspect the coverage gaps, broken sources, rights backlog and audience questions. Quarterly: review brand consistency, product claims and restoration of an asset backup. Revise this plan when the evidence changes.
